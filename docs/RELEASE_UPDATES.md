# Release & Auto-Update Setup

Climeto PWP uses `electron-updater` with a **generic** update feed.

## 1. Build a release

```bash
npm run electron:build
```

Outputs in `release/`:
- `Climeto PWP Setup X.Y.Z.exe` (NSIS installer)
- `latest.yml` (update metadata — required for auto-update)

## 2. Publish files to update server

Upload **both** to your CDN/server:

```
https://api.climeto.in/desktop/stable/
├── latest.yml
└── Climeto PWP Setup 1.0.1.exe
```

`latest.yml` example (generated by electron-builder):

```yaml
version: 1.0.1
files:
  - url: Climeto PWP Setup 1.0.1.exe
    sha512: ...
    size: ...
path: Climeto PWP Setup 1.0.1.exe
releaseDate: '2026-08-31T10:00:00.000Z'
```

## 3. Client behaviour

| Event | When |
|-------|------|
| Check on startup | 15s after app launch (packaged builds only) |
| Periodic check | Every 4 hours (`UPDATE_CHECK_INTERVAL_MS`) |
| Real-time UI | `UpdateBanner` shows download progress + restart prompt |

## 4. Environment variables

| Variable | Default | Purpose |
|----------|---------|---------|
| `UPDATE_FEED_URL` | `https://api.climeto.in/desktop/pwp/releases` | Update feed base URL |
| `UPDATE_AUTO_DOWNLOAD` | `1` | Auto-download when update found |
| `UPDATE_CHECK_INTERVAL_MS` | `14400000` | Periodic check interval |

## 5. Version bump

Before each release, bump `version` in `package.json`:

```json
"version": "1.0.1"
```

Sentry release tag uses the same version: `climeto-pwp@1.0.1`.

## 6. Telemetry endpoint (backend)

Desktop app POSTs batched events to:

```
POST /api/pwp/telemetry
Authorization: Bearer <login-token>

{
  "events": [
    {
      "event": "app_session_start",
      "appVersion": "1.0.1",
      "machineId": "...",
      "sessionId": "...",
      "sentAt": "2026-08-31T10:00:00.000Z"
    }
  ]
}
```

Disable with `TELEMETRY_DISABLED=1`.
